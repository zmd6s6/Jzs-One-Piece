# Oracle 名字解析、同义词与权限："表不存在"的两种含义

> 阅读提示：这是本仓库《AGENTS.md · 写作规范》中事故记录格式的样板——包含完整的事件链路、思考链路和层层剖析。文中账号与表名已脱敏：账号 W（业务属主）、账号 R（只读）、账号 H（另一个业务的属主）；表 A/表 B（属于 W 的业务表）、表 C（属于 H 的功能表）。

## 一、事件链路（时间线还原）

1. **T0**：客户现场，程序日志持续报错 `ORA-00942: 表或视图不存在`，对应的 SQL 是一条三表关联查询：`FROM 表A JOIN 表B JOIN H.表C`（表 C 显式写了 `H.` 前缀，表 A/B 没写前缀）。
2. **T1**：实施工程师用 SQL 工具（Navicat）连现场库，**用只读账号 R 手动执行同一条 SQL——成功返回数据**。改用账号 H 执行——报"表不存在"。用账号 W 执行——正常。
3. **T2**：因为"手动正常、程序报错"，怀疑转向程序侧：连接配置被覆盖？程序连了另一个库？于是对照了研发环境：同一接口在研发、测试环境实测都正常，且在库端抓到证据——执行该 SQL 的正是配置里写的只读账号 R。
4. **T3**：排查一度聚焦在"表名解析"上（第二节会讲为什么这条线看起来非常有说服力），但始终解释不了"程序用的账号手测正常、程序却失败"。
5. **T4**：DBA 介入检查现场库的授权——**根因落定：现场库缺少授权**。程序所用账号对某几张表没有 SELECT 权限；补上授权后，程序立刻恢复正常。

## 二、思考链路（当时的推理过程）

**第一反应：表真的不存在？** → 用 SQL 工具手测，成功返回数据 → 排除"表不存在"。**（这个排除是被错误信息骗了，见第三节。）**

**第二反应：为什么换账号结果不同？** → 发现 SQL 里表 A/B 没写前缀，而 Oracle 的规则是：**未加前缀的表名按"当前连接账号"解析**（类比：说"302 房间"时，指的是"你所在这栋楼的 302"，不同楼的人理解不同）。账号 W 自己拥有表 A/B，账号 R 建了**同义词**（synonym，可以理解为"别名登记"：在 R 名下登记一个名字指向 W 的表），所以它们都能解析；账号 H 既不拥有也没登记 → 报"表不存在"。**这条线解释了 H 为什么失败，且在研发库上复现验证成立**——但程序用的不是 H，解释不了程序。

**第三反应：程序的连接信息被覆盖了？** → 三环境对照：研发库的执行历史（`v$sql` 视图记录每条 SQL 是谁执行的）显示执行者就是配置写的账号 R；程序配置、环境变量、镜像内置配置逐层核对无覆盖。排除。

**第四反应（DBA）：回到错误本身。** `ORA-00942` 这条报错有**双重含义**——"表不存在"**或者**"你没有这张表的权限"。Oracle 出于安全考虑故意不区分（不向无权限者泄露对象是否存在）。手测用的账号恰好有权限，程序用的账号没有 → 一切矛盾瞬间闭环。

## 三、层层剖析

**表象**：同一条 SQL，手动执行正常、程序报"表不存在"。

**直接原因**：程序连接用的账号对查询涉及的一张表**没有 SELECT 权限**，Oracle 统一报 ORA-00942。

**机制原因**（为什么排查被带偏这么久）：
1. **ORA-00942 的双重含义**——"不存在"与"无权限"共用一条报错，仅看文字无法区分；
2. **名字解析规则放大了迷惑性**——SQL 混用了"带前缀"和"不带前缀"两种写法，导致不同账号手测结果不同，把注意力牢牢引向"解析"而非"权限"；
3. **手测账号 ≠ 程序账号**——"我手动能跑"证明的是"我这个账号有权限"，证明不了程序账号有。

**流程原因**：新环境交付缺少"**账号权限基线核对**"这一步。开发库的授权是多年手工积累的，从未沉淀成可重放的授权脚本，新库部署时自然漏掉。

## 四、修复

```sql
-- 现场补授权（一次性）
GRANT SELECT ON 表属主.表名 TO 程序账号;
```

## 五、预防（落到检查项，不靠"下次注意"）

1. **交付前权限核对**：以**程序账号**登录，执行
   ```sql
   SELECT count(*) FROM all_tables WHERE table_name = '目标表';
   ```
   返回 0 就是"看不到"——**要么不存在要么没权限**（all_tables 只列出当前账号有权限看到的表，这正是核对原理）。逐表核对，全过才算交付完成。
2. **授权脚本进版本库**：把"哪个账号需要对哪些表的什么权限"写成 SQL 脚本，随部署清单走，新环境一次执行。
3. **SQL 书写约定**：跨账号访问的表**一律写 `前缀.表名`**（要么全带前缀，要么全靠同义词），不混用——混用是本次排查被带偏的结构性原因。
