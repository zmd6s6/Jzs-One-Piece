# Wi-Fi 满格为什么仍然卡：无线链路的基本限制

## 先用生活场景理解这个问题

手机明明显示 Wi-Fi 满格，视频依然卡顿。为什么“信号强”不等于“下载一定快”？因为无线信号质量只是整条通信路径中的一部分。

## 本篇新术语，逐个落地

- **Wi-Fi**：设备通过无线电波连接局域网的一组技术标准，像无需网线的入口。
- **以太网**：常见的有线局域网传输方式，像有实体线缆的入口。
- **干扰**：其他设备/信号让无线传输更困难，像对讲机频道里有杂音。
- **丢包和重传**：数据未成功到达而需要重新发送，类似快递丢件后补送。

**学习前置**：[家庭网络与 Wi-Fi 接入点](./home-network-devices.md) → [本地如何交换数据](./ethernet-switch-arp.md)。先能用自己的话解释这些知识，再看下面的技术机制。

**不改配置的最小观察**：先查出家里网关 IP；对网关进行多次 ping 测试，和对公网地址的测试结果分开记录，避免把运营商远端问题误判为无线故障。

## 再把生活里的问题对应到真实网络
Wi-Fi 信号格数满，但语音断续、视频卡顿。因为信号强度只表示无线接收条件的一部分，并不等于排队少、重传少或外网路径畅通。

## 三个关键概念
- **共享介质**：多个设备共用同一无线信道的通话机会，类似多人轮流使用对讲机。
- **干扰与重传**：帧损坏或无法确认可能重新发送，增加有效传输时间。
- **抖动（jitter）**：各个数据包的时延不稳定，类似每单配送到达时间忽快忽慢。

Wi-Fi 在链路层和物理层与有线以太网不同，但可以同样承载 IP、TCP、UDP 等协议。

## 动手
在同一目标上分别用有线、无线连续测试几十次：
```bash
ping -c 20 192.168.1.1
```
Windows 改为 `ping -n 20 192.168.1.1`；示例网关地址请替换成你实际的网关。观察丢包比例和最大/最小延迟，不要只看均值。

## 避坑
- Ping 结果受 ICMP 限速影响，不能单凭丢几个回包认定 TCP 业务一定丢包。
- 排查时分别测试“到本地网关”和“到远端服务”，区分无线接入与上游问题。
