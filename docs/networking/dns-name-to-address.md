# 为什么输入网站名字，就能找到对应的电脑

## 先看生活中的难题

你知道一家餐厅叫“街角面馆”，却不知道它在哪条街。你会打开地图搜索店名，然后得到位置。**网站的名字与网络地址之间，也需要一套“查询通讯录”的办法。**

- **域名**：人容易记住的名字，例如 `example.com`。它就像店名，不是服务器固定的物理地址。
- **IP 地址**：用于网络传递的地址。可以类比地图给出的目的地地址，但真实网络可以通过很多不同设备、转发与负载均衡实现服务。
- **DNS（域名系统）**：负责查询名字对应哪些记录的一套分布式系统。像“查通讯录”，不是负责运输网页的道路。

**为什么需要它？** 网站可能更换机器或分布在多个地址上；用户仍希望输入同一个名字。

## 一次简化的查询

1. 浏览器准备访问 `example.com`，需要知道可以连接的网络地址。
2. 电脑可能先从已有结果中寻找答案（**缓存**，像刚才查过的地址临时记在小本子上）。
3. 如果没有可用答案，就向配置的 DNS 解析服务询问，获得一个或多个结果。
4. 浏览器或系统据此尝试连接目标；**DNS 查询成功 ≠ 网页服务一定可以访问**。

DNS 的查询可能经过递归解析器和权威 DNS 服务器。你现在只需要区分：有人负责帮你查询，有人负责保存某个域名真正声明的答案；不是每次都一路从根服务器重新查一遍。

## 新术语落地：记录与缓存

DNS 结果不是“名字只对应一个 IP”的单项表，而是分不同用途的**记录（record）**：

| 记录 | 白话意思 | 最小例子（概念示意） |
|---|---|---|
| A | 给出 IPv4 地址（常见的四段数字形式） | `service.example → 192.0.2.10` |
| AAAA | 给出 IPv6 地址（更长、冒号分隔的形式） | `service.example → 2001:db8::10` |
| CNAME | 告诉你“请改查另一个名字” | `www.example → service.example` |

表里的 `192.0.2.10` 与 `2001:db8::10` 是文档保留地址，仅用于演示，并不声称真实可连接。

DNS 记录通常带有 **TTL（生存时间）**，告诉缓存答案能保留多久，就像地址簿上的有效期限。**负缓存**则是把“这个名字不存在”（常见结果是 NXDOMAIN）暂时记住。更新记录后是否立即生效，受各层解析器缓存策略影响，不能假设“固定等 30 秒就好”。

## 亲手验证：只查名字，不碰网站内容

打开系统命令行运行：

```bash
nslookup example.com
```

结果一般会显示使用了哪个 DNS 服务器、查询到的地址。接着执行：

```bash
nslookup www.example.com
```

看是否相同；不同名字不保证指向相同地址。你也可以多次查询对比，**结果不变不足以证明缓存一定命中**，结果变化也不一定是故障。

如果返回“查不到”，先区分域名拼写、当前网络的 DNS 配置，以及是否发生了负缓存；不要立刻认定浏览器或服务器坏了。
