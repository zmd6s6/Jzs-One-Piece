# DNS：名字是怎么变成地址的

## 先看一个现象

你在浏览器输入 `www.example.com`，回车，页面打开了。但这台服务器在地球另一端，电脑怎么知道该把请求发给谁？——在发出任何 HTTP 请求之前，电脑先干了一件事：**把名字翻译成 IP 地址**（比如 `192.0.2.1`（示意地址））。干这件事的系统就叫 **DNS（Domain Name System，域名系统）**。

一个贴切的类比：**DNS 就是互联网的电话簿**。你手机通讯录里存的是"张三 → 138xxxx"，不用背他的号码；DNS 存的是"www.example.com → 192.0.2.1（演示映射，并非该域名的实际解析结果）"。

## DNS 里存的是"记录"，记录有类型

电话簿里一行就是一个"号码"；DNS 里一行叫一条**记录**，常见类型只有两种需要先记住：

| 记录类型 | 意思 | 类比 |
|---|---|---|
| **A 记录** | 名字 → IP 地址 | "张三 → 138xxxx"（直接给号码） |
| **CNAME 记录** | 名字 → 另一个名字 | "老张 → 张三"（"你找张三的号码去"） |

关键区别：**A 记录直接给出最终答案（IP），CNAME 只给"再去查谁"**。查到 CNAME 后系统必须继续把那个名字查到底、拿到 A 记录为止。

> 自己动手看一眼（Windows 命令行）：
> ```text
> nslookup www.example.com
> ```
> 输出里的 `Addresses:` 就是查到的 A 记录。

## 查询的过程（简化版）

1. 电脑先问**本机缓存**："这名字我最近查过吗？"
2. 没有就问配置的 **DNS 服务器**（比如公司的、运营商的，K8s 集群里是 CoreDNS）；
3. DNS 服务器没有就继续往上级问，直到问到**权威服务器**（名字的主人自己公布答案的地方）；
4. 答案沿路返回，**每一层都会缓存一份**。

## 缓存与 TTL：答案会被记住一阵子

每条记录有个 **TTL（Time To Live，存活时间）**，意思是"这个答案你可以记 X 秒，过期前别再来问"。这就是为什么改了 DNS 解析后，有人立刻生效、有人要等一会儿。

**容易忽略的坑：查不到也会被缓存**。如果某次查询返回了"查无此名字"（**NXDOMAIN**），这个**否定答案也会被缓存**一小段时间（叫**负缓存**）。后果是：你刚把配置改对了，马上测试——还是失败！不是没改对，是那台 DNS 还记着"查无此名"。**应先检查负缓存的实际 TTL 和解析器缓存策略，再复测；不要假定固定等待几十秒就一定生效。**
