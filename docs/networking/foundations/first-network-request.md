# 浏览器打开网页时，究竟发生了哪些事

## 先看一个现象
浏览器输入 `https://example.com`，过一会儿看到网页。它不是“把一个网址传出去”这么简单，而是多次协作：找地址、连接、验证身份、请求、返回、渲染。

## 把参与者认清
- **客户端**：主动发请求的程序，类似点餐顾客（例如浏览器、Qt 客户端）。
- **服务端**：监听并处理请求的程序，类似后厨（例如 Java 服务）。
- **网络包**：网络中承载一部分数据的单元，类似一个个装着货物的快递。
- **时延（latency）**：一个操作的等待时间，类似配送要耗时；**带宽（bandwidth）**：单位时间理论上能运多少货，不能直接当成低延迟。
- **协议（protocol）**：双方共同遵守的格式和交互规则，类似点餐需要统一菜单与票据格式。

## 一条典型 HTTPS 请求的顺序
1. 浏览器解析 URL：协议名、主机名、路径。
2. **DNS** 把主机名解析到可连接的 IP（可能命中缓存）。
3. 操作系统查路由表，决定把流量从哪个网络接口送出去。
4. 如果走 TCP，双方通常先建立 TCP 连接；HTTPS 还需进行 TLS 安全协商。HTTP/3 走 QUIC，不能机械套用 TCP 握手。
5. 客户端发 HTTP 请求，服务端返回状态码、响应头和响应体。
6. 浏览器解析内容并可能继续请求图片、JS 等资源。

这是概念流程，不代表每次都逐项新建：连接可能被复用，DNS 有缓存，HTTP/3 与 HTTP/1.1 路径不同。

## 动手观察
在任意可用终端运行：
```bash
curl -I https://example.com
curl -v https://example.com -o /dev/null
```
Windows PowerShell 若 `curl` 是别名，用 `curl.exe`。观察解析、连接与 TLS/HTTP 信息；不同系统的 curl 构建输出可能不同。
