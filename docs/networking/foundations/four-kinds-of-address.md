# 域名、IP、MAC、端口分别回答什么问题

## 先看一个现象
配置里同时出现 `api.example.com`、`10.0.0.8`、`443`，抓包里还有 `00:11:22:33:44:55`。它们不是四种写法的同一个地址。

## 四个问题，对应四个身份
- **域名**：人类可记忆的名字，例如 `api.example.com`；类似通讯录联系人。通过 DNS 可获得地址。
- **IP 地址**：网络层的主机或接口寻址信息，例如 `192.168.1.10`；类似城市中的地址。
- **MAC 地址**：链路层硬件接口使用的标识，例如 `00:11:22:33:44:55`；可类比同一小区内的收件箱标签。不要误认为它全网唯一且永不变化。
- **端口**：传输层把数据交给哪个进程/服务，例如 `443`；类似到一栋楼后找几号窗口。同一数字在 TCP 和 UDP 中属于不同的端口空间。

```text
https://api.example.com:443/v1/orders
        域名          端口   路径
DNS 得到 IP → 路由选下一跳 → 邻居解析得到下一跳链路地址 → TCP/UDP 交给服务端端口
```

## 为什么 IP 不是最终答案
IP 到达某台机器，系统还需要按 TCP/UDP 端口分发给正确的监听端点。同一服务器能同时跑多个服务；但 `TCP 443` 和 `UDP 443` 是不同的通信入口。

## 验证
```bash
nslookup example.com
```
Windows 用 `ipconfig /all` 查地址、网关和网卡物理地址；Linux 用 `ip addr`。对比它们扮演的角色。

## 容易混淆
- 域名不是“固定指向一台服务器”，可解析为多个地址，且受缓存影响。
- 端口开放不代表业务应用层健康。
- MAC 主要用于当前链路的交付，不是公网跨路由器的最终目的地址。
