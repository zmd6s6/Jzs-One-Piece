# 电脑怎么把一张图片变成能传输的数字

## 第一件难以想象的事：网线里没有“图片”

你把一张照片发给朋友。看上去你发送了一张完整的图片，但计算机实际处理的是许多数字。网络设备传送的是这些数字对应的信号，不会把整张照片原样塞进一条网线。

想象把一篇文章拆成字符编号，按编号逐个记录；收件人按约定的方法还原，才能重新看到文字。

## 从数字 0 和 1 开始

**比特（bit）**：最小的二进制信息单位，只有 `0` 或 `1` 两种值。可以类比一盏灯“关/开”。

**字节（byte）**：通常由 8 个比特组成。像把 8 盏灯排成一组，最多可以表示 `2^8 = 256` 种不同组合。

**二进制**：只用 0 和 1 表示数字的一种计数法。十进制的 5 写成二进制为 `101`；用满 8 位写成 `00000101`。先不用记进制转换公式，只要知道 IP 地址计算会使用这样的数字表示。

**编码**：约定数字如何还原成文字或其他含义。比如 UTF-8 是常用的文字编码；并不是“一个汉字等于一个字节”。

## 为什么不能把一张大图片一次性塞过去

发快递时，大批货物通常分箱运输。网络上也常把要传的数据组织成适合当前协议和链路的单位：

- **包（packet）**：通常泛指网络上传输的一份数据；严格来说，不同层还有数据报、帧、段等不同名称。
- **头部（header）**：每份数据携带的控制信息，像包装箱上写的目的地、类型等标签。
- **载荷（payload）**：真正承载的那部分内容，像箱子里面的货。

例如一份文档要发给朋友，底层可能经过多份数据单位传送。**某一次读取到半份内容，并不能直接判断文件坏了**：读取多少数据与应用消息完整性是不同问题。

## 两个很快就会用到的例子

**例子一：IPv4 地址。** 你以后看到 `192.168.1.10` 时，需要知道这种地址本质上有 32 个比特，只是为了好读被分成了四组。后面的“/24、/27”就是根据比特位数划分网络范围，详见[IP/子网](../ip-subnet-and-routing.md)。

**例子二：TCP 数据。** 应用写入 100 个字节，不保证另一端一次就读到 100 个字节；因此需要[消息边界](../programming/tcp-message-framing.md)规则。

## 马上亲手看一次

不用安装软件：打开电脑的计算器，切换到程序员模式（部分系统提供），输入十进制 `5`，观察二进制显示是否为 `101`（或左侧补零的形式）。

有 Python 环境时还可以执行：

```bash
python -c "s='A中'; print(s.encode('utf-8'), len(s.encode('utf-8')))"
```

它通常显示 ASCII 字母与汉字编码后占用的字节数不同。这里 Python 只用于观察，完全不懂编程也可以跳过，理解“文字先变成数字”就够了。
