# 第一阶段：网络世界的基本规则

不用懂 HTTP、TCP 或任何协议，从“为什么点开网页能看到远方内容”开始。先知道数字是什么，再看通信任务为什么需要分工。

假设你打开网页，却看到“无法访问此网站”。先别背协议名：你需要知道谁在通信、数据走过哪些环节，以及如何辨别卡在了哪里。

## 按路径学

1. [浏览器怎样从网站拿到内容](./first-network-request.md)——只认识客户端、服务器、请求和响应
2. [一张图片在电脑里怎样变成 bit 和 byte](./bits-bytes-and-packets.md)——先懂二进制和数据块
3. [为什么网络通信要分工、封装](./layers-and-encapsulation.md)——认识不同岗位
4. [域名、IP、MAC、端口各解决什么定位问题](./four-kinds-of-address.md)——认识不同地址

## 按症状找
| 现象 | 先学 |
|---|---|
| 浏览器能打开 IP，打不开域名 | [四种地址](./four-kinds-of-address.md)，再看[DNS](../dns-name-to-address.md) |

## 本阶段如何验收

不使用协议缩写，画出“浏览器请求—远方回应”并用自己的例子解释 bit、byte 和四类定位标识。

不能独立解释时，请回到首次出现该名词的文章，而不是重新背一遍缩写。

## 按决策查
- 还不能画出“电脑 → 网关 → 服务器”的路径，就不要先钻 TCP 参数。
- 每个概念至少能用自己的话描述，并给出一个真实的地址或命令示例。
