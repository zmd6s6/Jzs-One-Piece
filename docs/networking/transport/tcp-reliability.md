# TCP 怎样保证字节有序：序列号、ACK、重传和接收窗口

## 先看一个现象
发送方调用一次 `send()` 写入 10000 字节，接收方 `recv()` 可能分多次返回数据。这不是丢包，而是 **TCP 保证字节顺序，不保存应用消息边界**。

## 四个机制
1. **序列号 SEQ**：标记字节流位置，像长卷宗的页码。
2. **确认号 ACK**：典型累计确认“下一个期望字节的位置”；像签收至第 N 页。
3. **重传**：超时或根据重复确认等迹象判断缺失数据后，重新发送相应字节范围。
4. **接收窗口 rwnd**：接收端告知“目前还能接多少”，避免发送速度压垮接收缓冲。

```text
发送：字节 100–199
接收：回复 ACK=200（说明期望从 200 开始）
如果 200–299 丢失，即便先看到 300–399，
累计 ACK 也不会直接跨过缺口。
```

实际 TCP 可能启用 SACK，额外报告离散接收区间，不能把“只会累计确认”当成完整实现。

## 如何验证
Wireshark 显示过滤器 `tcp.analysis.retransmission`、`tcp.analysis.duplicate_ack` 能辅助观察；这些是分析器推断标签，不等于无歧义的网络故障根因。抓包需关注是否同时看到双向流量。
