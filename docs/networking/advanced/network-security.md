# 网络安全边界在哪里：防火墙、TLS、鉴权和零信任

## 先用生活问题理解这一篇

办公楼门口已经刷卡，进到楼里的某位员工却不能随意查看所有人的档案。网络也要区分“能连进来、对方是谁、对方有权做什么”。

## 这些专业词分别是干什么的

- **防火墙**：控制哪些通信可以通过的规则或设备，像大楼入口门禁。
- **TLS**：保护内容并验证通信方身份的机制，像带身份核验的密封信。
- **认证（authentication）**：确认“你是谁”，像查看证件。
- **授权（authorization）**：确认“你可以做什么”，像检查这个人是否有档案室权限。
- **零信任**：不把内网来源直接等同于可信，按实际身份和访问条件持续验证。

**前置知识**：[端口是什么](../foundations/four-kinds-of-address.md) → [HTTPS 的保护](../application/https-tls.md) → [分层排障](../operations/troubleshooting-order.md)。

**最小观察或推演**：给一个“公司内部系统”分别列出网络放行、登录确认、数据阅读权限三道检查，说明为什么只开放或关闭某个端口不能解决全部安全问题。

## 再回到真实技术现象
服务器只开放内网 443，但某个未授权用户仍能调用敏感接口。因为**网络隔离**和**应用授权**是两种不同防线。

## 四道不同的门
- **防火墙/安全组**：按 IP、端口、协议等限制流量，像大楼门禁；它不懂每个业务用户是否能查看某患者记录。
- **TLS**：提供安全传输、服务端身份验证等能力，类似带身份核验的加密专线。
- **身份认证 Authentication**：识别是谁，类似查证件。
- **授权 Authorization**：决定能做什么，类似查岗位权限。
- **零信任**：不因为“来自内网”就天然放行，持续在合适的层面验证身份、设备状态和访问权限。

## 常见误区
1. 只用 IP 白名单无法替代业务授权。
2. HTTPS 加密不意味着服务端应用没有注入、越权等缺陷。
3. “服务只有内网能访问”不等于安全：横向移动、SSRF 和错误代理转发仍可能成为路径。
4. 生产抓包可能包含认证 Cookie、令牌与隐私数据；采集范围需要授权，归档与共享需脱敏。

## 最小检查清单
服务监听范围、边界规则、证书校验、用户身份、资源权限、审计日志、敏感数据保留策略分别确认。
