# 浏览器为什么显示小锁：HTTPS、TLS 与证书在保护什么

## 先想一个危险的场景

你在咖啡馆连接公共 Wi-Fi，然后登录网站输入密码。如果一段通信内容像明信片一样沿途可以被查看或修改，就可能泄露隐私。

此前你学过：**[HTTP](./http-core.md)负责客户端与网站怎样提问、怎样回答**。HTTP 的通信语义本身并不能保证每段数据都不被旁观者读到。我们还需要给对话增加安全保护。

## 先区别两个名字

- **HTTPS**：可以理解为“受到安全保护的 HTTP”。网站仍然使用 HTTP 的请求与响应含义，只是传输经过安全通道。
- **TLS（传输层安全协议）**：帮助通信双方协商加密方式、确认身份与保护数据完整性的安全机制。像双方先建立一条带身份核验的密封通道，再在其中交换内容。

HTTPS 并不意味着网页内容一定可信，也不能代替登录授权、服务端漏洞防护。

## 三个安全目标：逐个想清楚

1. **保密（机密性）**：路上其他人即使看见传输内容，也不应轻易读出你的密码。类似把信装进密封并加锁的信箱。
2. **防篡改（完整性）**：有人中途偷偷修改金额，收信方应能发现。类似密封件被动过会留下可验证的痕迹。
3. **证明对方身份（认证）**：你不只想要一条加密通道，还得确认对面确实是要访问的网站，不能把密码安全地“加密发送给骗子”。

第三件事往往依靠**证书（certificate）**与可信机构建立的验证链。证书可类比“由受信机构签发、声明网站身份的证件”。浏览器还会核对证书是否适用于正在访问的域名；**有证书不代表整个网站业务安全**。

## 网页中 HTTPS 怎样出现

```text
先知道访问目标的位置
      ↓
与对方建立能够通信的传输路径
      ↓
协商安全通道，检查对方身份证明（TLS）
      ↓
通过安全通道发出“我要哪个页面”（HTTP）
      ↓
接收并验证安全保护下的回应
```

这是一条便于理解的**常见 TCP + TLS 路径**。HTTP/3 通常走 QUIC，QUIC 内部集成 TLS 1.3 相关安全握手，不能说所有 HTTPS 都必须按相同 TCP 顺序建立。

## 亲手看一次，而不是死背“握手”

使用浏览器打开 `https://example.com`，点击地址栏附近的网站连接信息，查看是否标记为安全连接；不同浏览器 UI 会不同。

装有 curl 时可运行：

```bash
curl -v https://example.com -o /dev/null
```

观察终端中是否存在证书校验或 TLS 连接信息。此命令可能受系统证书库、代理、curl 构建选项影响，实际输出会有差异。

**不要用 `curl -k` 或关闭浏览器证书验证作为永久修复**：这只是跳过了本来应该确认的对方身份。
