# Nginx 返回 502/504 时，代理和上游分别出了什么问题

## 先用生活问题理解这一篇

你拨打客服总机，客服把你转给不同部门。你不知道具体是哪位客服接单，也可能因为转接站忙而一直等。这就是理解代理和负载均衡的入门画面。

## 这些专业词分别是干什么的

- **反向代理**：代表后方一个或多个服务器先接收客户端请求，像公司总机。
- **上游服务**：反向代理后面真正处理业务的程序，像被转接的客服。
- **负载均衡**：把请求分给多台服务实例，像前台分配不同窗口。
- **502**：一种网关收到无效上游响应等异常时可能返回的 HTTP 状态码。
- **504**：一种网关在规定时间内没有得到上游所需响应时可能返回的 HTTP 状态码。

**前置知识**：[HTTP 状态码](../application/http-core.md) → [端口拒绝与超时](../tcp-udp-refused-vs-timeout.md) → [排障顺序](./troubleshooting-order.md)。

**最小观察或推演**：画出“浏览器 → 代理 → 两个后端”的图。想想浏览器看到 504 时，哪个后端可能还在继续工作？为什么不能只看浏览器的一条报错定位根因？

## 再回到真实技术现象
浏览器访问同一域名，网关返回 502 或 504；后端某个节点直连却正常。这提示需要考虑**中间代理/负载均衡器**，不能简单把错误等同于某个业务接口报错。

## 两种角色
- **反向代理**：代表一个或多个后端对外接收请求，像大堂前台；客户端不直接知道所有后端地址。
- **负载均衡**：把请求分配给不同后端，像前台按忙闲情况安排窗口。

这些组件可以叠加 TLS 终止、路径改写、限流、连接池、健康检查等职责。

## 502 与 504 的典型含义
- **502 Bad Gateway**：网关收到无效的上游响应或上游交互异常，具体由代理实现与配置决定。
- **504 Gateway Timeout**：网关在其超时期限内未得到上游所需响应。
不能从状态码直接精确断定是“后端宕机”“数据库慢”或“网络断了”。

## 用路径思维查
```text
浏览器 → DNS → 入口 IP/TLS → 反向代理 → 上游连接 → 应用服务 → 数据库
```
先确认网关日志中的上游地址、连接/响应耗时，再查上游监听、路径和应用日志。检查代理是否走了错误的 IPv4/IPv6、网络命名空间或 DNS 缓存。

## 自测
为什么浏览器看到 504 时，后端进程仍可能正在处理这次请求？负载均衡健康检查通过能保证每个接口都健康吗？
