# NAT 与端口转发：公司总机是怎么工作的

## 先用生活场景理解这个问题

家里多部手机都能上网，可对外看起来可能使用同一个公网地址。这好比一栋写字楼有许多分机，对外只有一个总机号码。

## 本篇新术语，逐个落地

- **私有地址**：通常在家庭或组织内部使用、不能直接当全球互联网公共路由目的地址的 IP。
- **公网地址**：面向全球网络路由使用的 IP 地址；实际分配与可达性还会受运营商配置限制。
- **NAT（网络地址转换）**：网络设备在转发过程中改写报文里的来源或目的地址等信息，像总机替分机对外报号码。
- **端口转发**：把入口地址的某个服务窗口对应到内网设备的指定窗口，像总机把特定分机号转给某人。

**学习前置**：[IP、子网与路由](./ip-subnet-and-routing.md) → [端口是什么](./foundations/four-kinds-of-address.md)。先能用自己的话解释这些知识，再看下面的技术机制。

**不改配置的最小观察**：画出“手机私有 IP → 家用网关 → 外部网站”的图，把 NAT 发生的改写位置标出来；不要在未授权的设备上改动端口映射。

## 再把生活里的问题对应到真实网络

公司对外只公布一个总机号码，外面的人打总机，前台按需把电话转到某台分机。外面的人**不知道也不需要知道分机号**，公司内部的分机变动也不影响对外号码。网络上大量技术本质上就是这个"总机 + 转接"的把戏，名字叫 **NAT（Network Address Translation，网络地址转换）**。

## 三种"转接方式"

| 术语 | 类比 | 网络上发生了什么 |
|---|---|---|
| **SNAT**（改来源） | 分机打出去，对方只看到总机号 | 内网机器访问外网时，把包的"来源地址"改成网关的公网 IP——这就是家里 N 台设备共享一个宽带 IP 上网的原理 |
| **DNAT**（改目标） | 打总机的人被转接到某台分机 | 包到达时，把"目标地址/端口"改写成内部某台机器，再送过去 |
| **端口转发** | "拨总机转 8080 找工程部" | DNAT 的具体形式：外部访问 `总机IP:某端口` → 固定转给 `内网某机器:某端口`（路由器里的"虚拟服务器/端口映射"就是它） |

**实现转接的"前台"通常是一张规则表**。Linux 上可能使用 **iptables / nftables** 等规则配置接口，具体由内核和网络组件实现，规则形如"凡是打到 10.43.0.10:8848 的包，改写成发给 10.42.1.5:8848"。

> 一个重要推论：**"总机号码"本身不属于任何一台机器**。它只是规则表里的一个记号——因此某些虚拟 IP 可能只对特定协议与端口进行转发，出现“TCP 服务可访问但 ICMP 无响应”的情况；是否支持 ICMP 仍应根据具体实现判断。

## 自己动手看一眼

```text
:: Linux 上查看 NAT 规则表（需要 root）
iptables -t nat -L -n | head -20
```

如果系统使用 iptables NAT 规则且已有对应配置，可能看到 DNAT 等记录；若系统使用 nftables、eBPF 等不同实现，不能据此命令无输出推断“没有地址转换”。
