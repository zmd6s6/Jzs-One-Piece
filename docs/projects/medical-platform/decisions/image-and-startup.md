# 选型：镜像与启动

> 返回[决策索引](../incidents/README.md)。机制地基：[classpath 白话](../../../backend/java-classpath-basics.md)。

## 1. 镜像分发：私有仓库 / 逐台导入

| 候选 | 什么条件下合适 | 优点 | 代价 |
|---|---|---|---|
| 私有仓库（registry:2） | 节点 ≥2、发版周级以上 | 推一次全节点可拉 | 多一个常驻服务；每节点要配 registries.yaml 并重启 |
| 逐台 `ctr import` | 单节点、严格断网、低频 | 零额外组件 | 每次发版逐台人工分发，漏一台=挂死 |
| Harbor 等大型仓库 | 多团队共用、需要扫描/权限体系 | 功能完备 | 对小环境过度配置 |

**本项目**：逐台导入（断网、两台机器、低频），配"逐台确认镜像存在"的门禁。**该换**：节点增加或发版变频繁时上 registry:2。

## 2. Java 产物形态与容器入口

| 候选 | 什么条件下合适 | 代价 |
|---|---|---|
| fat jar + `java -jar` | 单体简单交付、无裸机双线 | 业务一改全量重建；与裸机交付形态不同 |
| thin(ZIP) + `java -jar -Dloader.path` | 与裸机脚本统一、且参数不会被漏 | **参数漏一个=全类加载失败**（[事故](../incidents/noclassdeffound-on-start.md)） |
| thin + `java -cp '/app/*:/app/lib/*' 主类` | 希望启动与布局解耦 | 需约定运行包目录结构 |

**本项目**：第三种——对任何布局免疫、通配不依赖文件名。**该换**：团队统一 fat jar 且无裸机交付时 `java -jar` 更省心；关键是**入口与布局成对固定**。

## 3. Dockerfile 放哪：源码仓 / CI 内联 / 部署仓

| 候选 | 什么条件下合适 | 代价 |
|---|---|---|
| 源码仓 | 默认应当如此 | 需改 CI 引用 |
| CI 内联 | 临时验证 | 与代码分叉演进、不可评审（事故来源） |
| 部署仓 | 构建与部署强耦合且运维主导 | 构建关注点泄漏、跨仓对齐难 |

**本项目**：源码仓，CI 只调用。**该换**：引入统一构建平台时可上收，但保持"构建定义随代码走"。
