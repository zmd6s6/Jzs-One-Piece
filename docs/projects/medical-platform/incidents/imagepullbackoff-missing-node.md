# 只有一个副本起不来，一挂就是几小时

> 先看：[端口："拒绝"与"超时"](../../../networking/tcp-udp-refused-vs-timeout.md)——本案例的失败形态是"反复去公网拉镜像然后超时"。

## 现象

双节点集群发布新版本后：一个副本正常，另一个一直报 `ImagePullBackOff`（"拉不到镜像，退避重试"），持续 5 小时。事件日志显示它在反复尝试连接 Docker Hub（公网镜像仓库）然后超时。

## 排查推理

1. 拉取行为说明**这台机器本地没有这个镜像**（本地有就不会去拉——默认策略 IfNotPresent 的含义）；
2. 这套环境**没有私有镜像仓库**，发布靠人工把镜像文件拷到每台机器导入；
3. 镜像明明发布过，为什么这台没有？→ **发布时只拷到了其中一台**。

## 根因

无仓库环境下"镜像分发到每台机器"是纯人工步骤，漏一台就是无限挂起；同服务另一个副本恰好在有镜像的机器上一切正常——**好副本掩盖了坏节点**。

## 修复

把镜像文件拷到缺失节点并导入：

```bash
k3s ctr -n k8s.io images import 镜像.tar   # 注意 -n k8s.io，忘写=看不到任何镜像
```

## 预防

1. 部署前**逐台**确认镜像存在（`ctr -n k8s.io images ls -q | grep <版本号>`），不过检查不许点部署——做成脚本门禁；
2. 节点多、发版频繁的环境直接上私有仓库（推一次全节点可拉），见[选型：镜像与启动](../decisions/image-and-startup.md)。
