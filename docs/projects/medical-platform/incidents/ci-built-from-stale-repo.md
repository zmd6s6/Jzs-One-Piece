# 构建流水线连着"另一个仓库"跑了两个月

## 现象

发布的版本号和源码仓库的最新代码对不上——产物里出现了两个月前的旧功能号。

## 排查推理

1. 第一怀疑"没拉最新代码"→ 检查流水线配置，发现仓库地址的组名拼错了；
2. 关键转折：**那个拼错的地址真实存在另一个同名旧仓库**（历史遗留副本）——所以构建一路绿灯，没有任何报错；
3. 结论：**HTTP 能访问 ≠ 是你想访问的那个仓库**（200 状态码只证明"有这么个地址"）。

## 根因

流水线配置指向了同名旧副本；发布流程中没有"核对构建源头"这一步。

## 修复与预防

1. 改回正确地址；旧副本仓库**归档或删除**（防止再有人连错）；
2. 发布记录必须登记"构建源仓库 + 版本号"，与发布单人工核对一次；
3. 长期方案：版本号与代码绑定（从 git 标签构建），见[选型：流程与工具](../decisions/process-and-tooling.md)。
