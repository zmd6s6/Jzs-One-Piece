# 部署产物多包了一层无用的壳

## 现象

发布的镜像产物是一个 zip，里面装着一个 tar（镜像文件）。实施同事每次部署都要"先解压再导入"，多一道纯手工工序。

## 根因

打包脚本沿用了通用压缩习惯，忘了**镜像 tar 本身就是成品**——导入命令（`ctr images import`）直接吃 tar，不需要（也没必要）先解压。

## 修复

打包阶段去掉压缩层，产物直接是 `.tar`。

## 预防（一条通用的判断标准）

**下游要拆开才能用的包装，每一层都要问"这层提供了什么价值"**——答不上来的包装层就是给所有下游加一道手工工序。同类检查：文件命名是否带版本（下游要重命名吗）、目录层级是否直白（要翻几层才到正文）。
