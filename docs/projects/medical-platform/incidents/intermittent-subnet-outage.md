# 跨网段"间歇性失联"：前半段通、上传阶段断

> 先看：[IP、子网与路由](../../../networking/ip-subnet-and-routing.md)（为什么"在一个公司"不等于"在一张网上"）和[端口："拒绝"与"超时"](../../../networking/tcp-udp-refused-vs-timeout.md)（判据）。

## 现象

发布流水线前半段（拉代码、编译）正常，到"上传产物"阶段**突然全部连不上目标网段**；过一阵又自己恢复。如此反复。

## 排查推理

1. 同一台构建机，前半段通 → **机器活着、部分路通**——排除构建机自身故障；
2. 失败集中在**特定目标网段** → 问题在子网之间的路上（中间设备/策略的间歇性），不在应用；
3. 用判据确认：失败全部是**超时**（不是"拒绝"）→ 包被路上丢弃，符合"路被挡"的特征（见[端口基础](../../../networking/tcp-udp-refused-vs-timeout.md)）。

## 根因

构建机所在子网与目标子网之间的路由/安全策略间歇性中断——网络层问题，应用无法自愈。

## 预防

把"各目标网段连通性探测"做成发布前检查（每个目标端口各测一遍），失败时**明确报告"网络不通，等恢复再试"**——避免盲目重跑整条流水线（一次几十分钟）浪费时间。
