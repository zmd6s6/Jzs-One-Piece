# 健康检查把好端端的程序杀了

## 背景

K8s 用"探针"（定期访问一个地址判断程序死活）决定要不要重启容器——本该是自愈机制。

## 现象

加了探针后，原本正常的服务开始**周期性被杀**。查日志：程序本身活得好好的，只是它的"综合健康报告"（`/actuator/health`，汇总数据库、注册中心等**所有**依赖的状态）因为某一个外部依赖抖动而返回失败。

## 根因

探针配在了综合报告上——任何一个依赖不好，报告就是"不健康"，K8s 就杀容器。**自愈机制被外部依赖劫持**：依赖抖一下，所有副本被轮流杀一遍。

## 修复

探针改打**分组端点**（Spring Boot 在 K8s 环境默认提供）：

| 端点 | 回答的问题 | 挂了会怎样 |
|---|---|---|
| `/actuator/health/liveness` | 进程还活着吗 | 杀掉重启 |
| `/actuator/health/readiness` | 能接客了吗 | 暂时不分流 |

它们不掺入外部依赖的状态。机制细节见[健康探针](../../../devops/kubernetes/internals/health-probes.md)。

## 附带教训："Running 是谎言"

没配探针的服务显示绿色 Running，只说明"容器没退出"，不代表功能可用——曾有服务数据库断连数天界面照样全绿。**验收看分组端点 + 真实业务请求，不看绿灯**。

## 慢启动保护

Java 服务冷启动可能要几分钟，普通探针等不了那么久会误杀。用 `startupProbe`（专门的启动期保护，给足 10 分钟容忍），不要把普通探针的延迟调很大。
