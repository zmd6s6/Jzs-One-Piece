# 计算机网络 9 个动手实验：从能看见包到能排障

> 这是独立于基础知识域的**练习工程与实践记录入口**。概念请先看[计算机网络零基础分阶段学习地图](../../networking/README.md)，实验环境、测试命令、观察结果和故障结论留在这里。

## 按路径做：依赖什么知识，再做哪个实验

**先完成实验 00**：这个实验只用浏览器，不需要学协议或编程。其余实验不必按编号死磕，请按照掌握的知识阶段挑选，先读左边的基础文章再动手。

| 实验 | 学到哪一步可以开始 | 真正要观察的事 |
|---|---|---|
| [00 浏览器观察一次请求与回应](./lab00-browser-observation.md) | 第一阶段：客户端与服务器 | 浏览器确实向对方获取内容，记录状态和耗时 |
| [04 ARP 与 ICMP](./lab04-arp-icmp.md) | 第二阶段局域网 + 第三阶段网络探测 | 本地地址与诊断工具为什么是两回事 |
| [03 子网路由](./lab03-subnet-routing.md) | 第三阶段：IP 和子网 | 算对网络范围，找出下一跳 |
| [05 TCP 握手抓包](./lab05-tcp-handshake.md) | 第四阶段：TCP 建连 | 找到 SYN/ACK 与连接状态 |
| [02 DNS 对比](./lab02-dns-observation.md) | 第五阶段：DNS 与 HTTPS | 解释名字解析和网页访问为什么不是同一次操作 |
| [01 本地 HTTP 服务](./lab01-http-local.md) | 第五阶段：HTTP 与端口 | 自己看一次请求与状态码，理解本地服务 |
| [06 TCP 消息分帧](./lab06-length-prefix.md) | 第六阶段：Socket 和字节流 | 两次发送不等于两次读取，如何正确收齐消息 |
| [07 Java × Qt 跨语言通信](./lab07-java-qt-echo.md) | 第六阶段：Java、Qt 与编码 | 统一字节序、长度与协议 |
| [08 综合故障定位](./lab08-network-debug.md) | 第七阶段：排障 | 提供有证据的诊断报告 |

## 按症状找
| 症状 | 实验 |
|---|---|
| 想知道请求发到哪里、返回了什么 | [01](./lab01-http-local.md) |
| 域名解析正常但服务不通 | [02](./lab02-dns-observation.md) + [08](./lab08-network-debug.md) |
| 怀疑握手异常、端口拒绝 | [05](./lab05-tcp-handshake.md) + [08](./lab08-network-debug.md) |
| TCP “粘包/半包” | [06](./lab06-length-prefix.md) |
| Java 与 Qt 互通需要统一协议 | [07](./lab07-java-qt-echo.md) |

## 按决策查
- 只在自有机器、环回地址或明确授权环境抓包/测试；避免未经许可扫描他人设备。
- 记录：目标、环境、预期、命令、观测、解释、与基础知识的对应关系。
- 同一个实验失败先保留输出，再修改条件；不要把假设写成已验证结论。
