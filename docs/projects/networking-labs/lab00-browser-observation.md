# 实验 00：只用浏览器观察一次请求和回应

## 为什么第一件事不是装 Wireshark

你第一次学网络，如果尚不理解“谁在问谁”，就去看几十种协议缩写，很难真正吸收。先用日常熟悉的浏览器看一次可观察的通信：**我打开了一个页面，浏览器从哪里得到内容？**

本实验不需要 Java、Python、命令行或抓包工具。

## 开始前只认四个词

- **浏览器**：你用来打开网页的程序，比如 Chrome、Edge、Safari。
- **客户端**：主动提出需求的一方，这里就是浏览器。
- **服务器**：提供网页内容的一方，通常是另一台机器上运行的网站程序。
- **请求 / 响应**：客户端提出需求 / 服务器给出回应，像点餐与上菜。

学完这四个词就够了；若不理解，先看[零基础第一课](../../networking/foundations/first-network-request.md)。

## 操作过程

1. 打开浏览器，新建一个标签页，输入 `https://example.com` 并打开。这里的 example.com 是专供文档示例使用的域名。
2. 按 `F12`，或通过菜单选择“开发者工具”。选择 **Network（网络）**。如果这个区域有“保留日志（Preserve log）”，可以暂时开启，避免刷新后记录消失。
3. 按 `Ctrl+R` 刷新页面。面板里可能出现一行或多行记录。
4. 点击页面文档所对应的记录（不同浏览器中可能叫 `document`）。观察：
   - **Name（名称）**：请求哪个资源；
   - **Status（状态）**：对方返回的结果编号。常见 `200` 表示请求成功处理；
   - **Size（大小）**：本次记录对应的数据量；可能包含从浏览器缓存读取的部分；
   - **Timing（耗时）**：这次获取内容花费的时间或阶段信息。
5. 再刷新一次，对比两次记录。**不要求两次完全相同**：浏览器可能复用连接、从缓存取内容，也可能受到扩展程序、代理影响。

如果用手机或平板且无法方便查看开发者工具，改用电脑浏览器，或只记录观察到的网页变化。

## 验收

1. 谁是发起需求的客户端？谁在提供内容？
2. 某条请求返回 404 或失败，是否足以证明“你的整台电脑断网”？为什么不行？
3. 为什么刷新一次页面可能出现多条记录？
4. 如果第二次刷新时没有明显网络传输，为什么不能直接说“网站从来没提供内容”？
