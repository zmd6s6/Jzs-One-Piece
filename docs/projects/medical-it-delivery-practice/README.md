# 实践项目：轻量集群交付体系的搭建（某医疗信息化产品线）

> 这是一次真实工作的记录：范围、约束、做法、妥协与复盘。
> 名词不熟先查[术语表](../../devops/k8s-glossary.md)；通用原理与事故细节分别见 [原理篇](../../devops/k3s-internals.md) 与 [事故篇](../../devops/k3s-incident-principles.md)；选型对比见 [ADR](../../devops/k3s-decision-records.md)。

## 1. 背景与约束（决定了后面所有选择）

医疗信息化产品线长期以"裸机 + systemd + 解压即运行包"的方式交付：一个 jar、一个 lib 目录、一个启动脚本。随着服务拆分与现场部署增多，出现了几类问题：环境差异靠人工核对、升级过程会短暂中断服务、回滚依赖人工备份。

于是推动容器化与集群化。但现实约束很硬：

| 约束 | 具体表现 | 对方案的影响 |
|---|---|---|
| 机器少 | 客户现场只能提供 2 台服务器；内部测试环境同样只有 2 台 | 双节点不是"推荐拓扑"，而是资源约束下的折中 |
| 断网 | 现场无外网，节点也不能访问公司制品库 | 镜像必须离线分发；不能依赖在线拉取 |
| 无专职运维 | 现场技术人员的日常重点是业务问题 | 方案要能"照手册执行"，不能依赖经验判断 |
| 中间件既有资产 | 数据库/缓存等由现场既有系统提供，不在集群内 | 需要把"集群外地址"以集群内名字引用 |

## 2. 负责的范围

- 集群选型与搭建（研发环境 + 客户/测试环境）；
- 三个后端服务（网关、平台、影像服务）的镜像化与启动方式统一；
- 制品与发布流程（构建、产物分发、部署、回滚、留痕）；
- 部署清单的工程化（分层模板、环境差异、脚本）；
- 排障手册与问题记录规范。

## 3. 建成的东西

```
镜像与启动    薄 jar + lib 目录（与裸机交付同形态）
             容器入口统一：java -cp '/app/*:/app/lib/*' 主类
             Dockerfile 放在各源码仓，CI 只负责调用

集群与运行    k3s（单二进制、离线安装）
             无状态服务用 Deployment，注册中心与影像服务用 StatefulSet
             集群外数据库/缓存：headless Service + 同名 Endpoints 提供名字

交付与流程    kustomize 分层：base（共性）+ 每个环境一个 overlay（差异）
             发布七步：准备 → 产物 → 分发到每个节点 → 配置核对 → 声明式部署 → 验收 → 观察留痕
             回滚：rollout undo / 版本回退 / 环境重建

知识与规范    术语表、事故复盘、选型记录、排障分层流程（L0-L6）、问题台账模板
```

## 4. 当时的妥协与遗留（如实记录）

这些不是"最佳实践"，是当时条件下的选择，列出来是为了以后判断能不能改：

1. **双节点**：资源只有两台。代价是引入了"镜像必须分发到两台"和"跨节点网络必须通"两个新问题域，也确实在这两处各出过一次故障；
2. **没有私有镜像仓库**：靠逐节点手工导入 + 每个节点逐一确认。发版频繁后这会是主要成本；
3. **本地目录存储（local-path）**：注册中心数据与影像临时文件绑在节点上，副本漂移会落到别的节点；
4. **注册中心单副本**：可用性上它是单点，当时按测试环境定位接受；
5. **探针后补**：早期没有探针，出现过"进程正常但依赖已断"却显示健康的情况；后来统一改为存活/就绪组端点 + startupProbe；
6. **配置双轨**：部分口令同时存在于 ConfigMap 与 Secret，存在改一漏一的风险，尚未完全收敛；
7. **环境差异靠 overlay 表达**，但个别字段（文件服务地址一类）仍在配置里硬编码，需逐环境校对。

## 5. 复盘：如果重来一次

- **拓扑**：资源允许时改为"1 控制面 + 多工作节点"，而不是两台同角色；并从一开始就把"镜像分发到全部节点"做成部署前的自动检查；
- **存储与中间件**：尽早引入网络存储或把有状态组件外置，避免"数据绑节点"；
- **镜像分发**：发版频率一旦上来就上私有仓库，而不是继续手工导入；
- **版本纪律**：从第一版就要求"从 tag 构建、版本号四处一致（tag / 镜像 / 制品 / 发布单）"，避免"同号不同物"；
- **探针与健康**：容器化第一天就配齐探针，并把"聚合健康端点不能用作探针"写进规范。

## 6. 常见问题索引（细节见事故篇）

| 问题 | 一句话 | 详细 |
|---|---|---|
| 容器启动即退出，类加载失败 | 镜像入口与打包布局不匹配 | 事故篇 二 |
| 容器不报错但反复重启 | 内存超出 limit 被内核杀掉 | 事故篇 一 |
| 服务日志报元数据空间耗尽 | 堆够但 Metaspace 上限太小 | 事故篇 一 |
| 只有一个副本起不来 | 镜像没分发的那个节点 | 事故篇 三 |
| 解析不到集群外数据库名字 | 用了 ExternalName 且目标是 IP | 事故篇 四 |
| 刚建的名字解析失败 | DNS 负缓存 30 秒 | 事故篇 四 |
| 改了配置不生效 | 单文件挂载不随配置更新 | 事故篇 六 |
| 探针周期性重启健康的容器 | liveness 打了聚合健康端点 | 事故篇 五 |
| 发版产物版本与源码不符 | 构建源指向了同名旧仓库 | 事故篇 七 |
