# 服务注册失败导致启动中断：8848 通不代表 9848 通

> 先看：[端口："拒绝"与"超时"](../../../networking/tcp-udp-refused-vs-timeout.md)——一个服务占多个端口，且互相关联。

## 现象

现场环境，网关类服务启动到最后阶段失败退出，日志链：

```text
Failed to start bean 'webServerStartStop'
  ← NacosServiceRegistry.register(...)        ← 向注册中心登记失败
    ← NacosException: Client not connected, current status:STARTING
```

其后跟着数据连接池关闭等日志——那些是**陪葬**（关闭时的清理动作），不是原因。

## 排查推理

1. 注册中心（Nacos）的客户端连不上 → 第一怀疑"注册中心没部署/地址写错"→ 查：部署了、地址对；
2. 怀疑版本不匹配 → 版本一致；
3. 关键动作：**测端口**。注册中心占三个端口——8848（网页）、9848/9849（内部通信，= 8848+1000）。结果：**8848 通，9848 不通**。

## 根因

防火墙只放行了 8848。程序连接用的是 9848 → 连不上 → 客户端停在 STARTING → 注册失败被当作致命错误 → 整个服务退出。**"网页打得开"只证明 8848 通**。

另一个现场变体：本机防火墙已关仍不通 → 用"拒绝 vs 超时"判读——全部**超时**说明中间网络设备在丢包（见[端口基础](../../../networking/tcp-udp-refused-vs-timeout.md)的"路不通"一节）。

## 修复

放行 9848/9849（与 8848 一起，三端口成套放行），服务即正常启动。

## 预防

1. 中间件的端口清单进交付文档，**成套放行**，并把"三端口逐一探测"写进部署前检查；
2. 加固建议（研发侧）：注册失败改为非致命（自动重试），避免"依赖抖一下整个服务起不来"。
